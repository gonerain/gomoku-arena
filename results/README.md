## 关键发现：这个 50% 不是水平相当

对棋谱做重复性检查（`python tests/analyze_series.py results/series_20261013_dsh_vs_codex.jsonl`）：

| 检查项 | 结果 |
|---|---|
| `DSH 执黑` 的 10 局 | 手数全部 = 35，**不同着法序列只有 1 条** |
| `Codex 执黑` 的 10 局 | 手数全部 = 33，**不同着法序列只有 1 条** |
| 种子是否影响棋局 | 不影响 —— 20 局其实只包含 2 盘不同的棋，各重复 10 次 |
| 胜负与颜色的关系 | 100% 由"谁执黑"决定 |

结论：**交换先手的设计在这里完全失效**，因为五子棋（free-style）的先手优势是压倒性的 ——
黑方在 15×15 上对完美应对处于必胜。交换先手只是把"必胜的黑棋"这份优势轮流发给双方，
于是无论两边强弱，结果都必然是 10:10。

因此这个系列**不能用来判断谁的模型更强**。它只证明了：

1. 两个引擎都能执行一套有效的黑棋取胜路线；
2. 两个引擎都不会在白方防守成功（都输给对手的黑棋）；
3. 平台侧一切正常 —— 身份、权重、版本隔离正确，20 局无任何判罚异常。

**下一届必须改赛制，否则再跑多少局都是 50%。** 可选方案：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 指定开局（推荐）** | 平台给一个平衡的开局（2~4 手），从该局面开始下并交换黑白 | 需要新增一个协议帧（如 `opening`）交给引擎，两边要配合改 |
| B. 只评黑棋 | 只统计双方执黑时的胜负与手数，承认白方没有反击空间 | 零改动，但信息量少（每方只有 10 局数据） |
| C. 开局库 + 交换 | 预置若干平衡开局，逐局随机选一个并交换黑白 | 需要建立并维护开局库 |
| D. Swap2 | 标准 Swap2 开局协议 | 最强，但引擎侧改动最大 |

## 复现方式

```powershell
cd D:\Code\platform
python -m gomoku_arena.batch_cli --config matchups\dsh_vs_codex.json --games 20 `
  --move-timeout 2000 --game-timeout 300000 --seed 20261013 --save

python tests/analyze_series.py results/series_20261013_dsh_vs_codex.jsonl
```

两个引擎都是确定性的：同样的身份/权重/种子会产出逐手完全一致的棋局。
本目录下的 `.jsonl` 是完整棋谱（含每手坐标与耗时），`.json` 是分色统计与逐局摘要。
